# Section 1 — Test Goal and Requirement Coverage

**Max score: 10 pts**

---

## Criteria

| # | Criterion | Status | Notes |
|---|-----------|--------|-------|
| 1.1 | Each test verifies the **business essence** of the scenario, not just UI clicks | | |
| 1.2 | Pass/fail criteria are **unambiguous** (clear assertion with a meaningful message) | | |
| 1.3 | Every test maps to a **named business scenario** (e.g., "user can add item to cart and checkout") | | |
| 1.4 | No test that only checks "element exists" without verifying business outcome | | |

---

## Checklist — ask yourself for each test

- [ ] If I describe this test to a non-technical stakeholder, do they understand what it protects?
- [ ] If this test fails, do I immediately know _what business behaviour is broken_?
- [ ] Is there a risk that the test passes but the feature is actually broken?
